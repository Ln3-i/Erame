# Changelog

本文件记录框架包的对外变更。版本号遵循 `MAJOR.MINOR.PATCH`：
新增能力升 `MINOR`，破坏性变更升 `MAJOR`（0.x 期间用 `MINOR` 表示破坏性变更）。

## 0.10.0

模块按能力域拆分、框架包去掉 Addressables 硬依赖。

### 模块粒度

- 原来的 `FrameworkModule` + `GameplayModule` 两个大盒子拆成**一个能力域一个模块**：
  `LogModule` / `EventsModule` / `TimeModule` / `AssetsModule` / `InputModule` /
  `UIModule` / `PoolModule` / `AudioModule` / `LocalizationModule` / `SaveModule` /
  `DataModule` / `FlowModule` / `CommandModule` / `SessionModule`。
- 每个模块只包含本域被勾选能力的注册行；**删能力 = 删模块文件和入口里的一行 `AddModule`**。
- 生成器按能力组逐个写模块文件，入口 `GameEntry` 的 `AddModule` 链也按本次选择生成。
- 模块文件带 `// <auto-generated>` 标记：重新生成时只覆盖带标记的文件；
  业务往模块里手写了注册（删掉了标记）就保留原文件，日志里给出提示。

### 依赖

- `package.json` 移除 `com.unity.addressables` 依赖：底座与启动壳已不含任何 Addressables 代码，
  不用资源的项目不该被迫安装它。
- 生成器在勾选**资源**（场景/音频会自动带入）时检查工程 `Packages/manifest.json`，
  缺 `com.unity.addressables` 会给出警告；生成窗口里也有对应提示。
  使用资源能力前请自行在 Package Manager 里安装 Addressables。

### 破坏性变更

- 生成的项目不再有 `FrameworkModule` / `GameplayModule`，改为按能力域的模块；
  已有项目重新运行一次「生成项目（按需）」即可得到新的模块与入口。
- 旧的 `FrameworkModule.cs` / `GameplayModule.cs` 可以手动删除（删除前确认入口里已不再引用）。

## 0.9.0

底座里不再有任何"要求业务实现"的能力契约；生成器从"全量生成再删"改为"按能力生成"。

### 底座（Erame.Core）

- 移除 `IEventBusDiagnostics`：诊断协议下沉到业务层 `Game.Runtime`（生成模板同步）。
  事件总线可以整体替换或删除，不会在底座里留下无人实现的接口。
- 编辑器「事件统计」不再引用具体事件总线类型：改为在容器里反射查找
  `GetSubscriptionCounts()`，找不到时只给一条警告。

### 生成器

- 新增窗口 **`Erame/示例/生成项目（按需）`**：按能力勾选生成。能力清单：
  日志 / 事件 / 时间 / Tick / 输入门闸 / 输入 / UI / 池 / 音频 / 本地化 /
  存档 / 数据 / 流程状态机 / 命令 / 会话 / 资源 / 场景。
- 只写选中能力的契约、实现与模块注册；基础能力（日志/事件/时间/Tick/门闸）必选，
  其余能力按依赖自动带入，窗口里会提示"需要一并生成"。
- 运行时文件改为**逐文件**判断：目标已存在则保留（不覆盖业务修改），
  因此可以随时再开窗口补生成新增能力。
- **`Erame/示例/生成项目（全部能力）`** 保留为全选快捷入口。

### 破坏性变更

- 菜单 `Erame/示例/生成项目示例` 改名为 `Erame/示例/生成项目（全部能力）`。
- `Erame.Core` 中 `IEventBusDiagnostics` 的声明已删除；包内
  `Runtime/Erame.Core/Event/IEventBusDiagnostics.cs` 只剩说明性注释，可手动删除该文件
  （以及对应 `.meta`）。

## 0.8.0

命名空间与程序集对齐：`Erame.Core` 只保留底座，业务契约/实现归 `Game.Runtime`；平台能力不再由框架提供。

### Core 底座

- `Erame.Core` 只保留：`ServiceContainer` / `ServiceScope` / `IService` / `IModule` /
  `IServiceRegistrar` / `IServiceProvider`、`ErameBuilder` / `ErameEntry` / `IErameEntry`、
  `Algorithms`、`Utils`、`LogLevel`。
- 新增 `IFrameUpdate` 底座协议：实现它的服务由 `ErameRuntime` 每帧统一驱动。
- 新增 `IEventBusDiagnostics` 诊断协议：编辑器事件统计不再依赖具体 `EventBus` 类型。
- `ServiceContainer` 新增 `GetAll<T>()`：按初始化顺序返回实现某协议的所有实例（按引用去重）。

### 业务层

- 领域接口、DTO、事件、实现全部移入业务程序集 `Game.Runtime`：
  契约命名空间 `Game.Runtime`，实现命名空间 `Game.Runtime.Services`。
- `TickService` 实现 `IFrameUpdate`；`ErameRuntime` 不再引用 `ITickService` / `IPlatformService`。
- `Game.asmdef` 引用 `Game.Runtime`；`Tests.asmdef` 引用 `Game.Runtime`。

### 平台能力

- 删除框架内的 `AddPlatformModule()` / `ProvidePlatformModule()` 平台模块机制。
- Steam / Epic / Wegame 平台包与平台抽象不再由框架提供；历史实现归档到
  `Samples~/Platform`（不参与编译，仅供参考）。
- 移除 `ErameSettings` 的 Steam AppID / 语言同步字段，移除 Steam 安装、切宏、
  `steam_appid.txt` 相关编辑器菜单与发布检查。
- `Packages/manifest.json` 移除 Steamworks.NET 依赖。

### 生成器与文档

- 生成器输出 `Game.Runtime.asmdef` + `Contracts/` + `Services/`，命名空间为 `__NS__.Runtime` /
  `__NS__.Runtime.Services`；已存在时保留业务修改。
- README / 开发手册更新 Core 底座、业务契约位置、平台能力自行实现说明。

## 0.7.0

面向"业务可改"的装配调整：`Erame.Core` 不变，Runtime 服务实现下沉到业务工程。

### 目录与程序集

- `Erame.Runtime` 只保留启动壳：`ErameMonoEntry` / `ErameRuntime` / `ErameSettings`；
  `InternalsVisibleTo("Erame.Runtime")` 无需调整。
- 新增 `Samples~/Runtime` 服务实现模板；`Erame/示例/生成项目示例` 会把它复制到
  `Assets/Game/Scripts/Runtime`，生成后归业务所有，可直接修改或删除；已存在时不覆盖。
- `Game.asmdef` 增加 `Unity.Addressables` / `Unity.ResourceManager` 引用；
  测试程序集需要额外引用 `Game`（运行时服务实现所在程序集）。

### 默认服务

- `ErameRuntime.Start` 不再注册默认服务；`ILogService` / `IEventBus` / `ITimeService` / `IInputGate`
  改由 `FrameworkModule` 注册。
- 删除某项默认服务只需删掉 `FrameworkModule` 对应注册行；替换实现只需注册同名接口
  （重复注册仍会直接报错，因此"替换 = 不注册旧实现"）。
- 容器快照中的默认服务来源标签由 `框架默认` 变为 `FrameworkModule`。

### 生成器与文档

- 生成器模板同步新的 `FrameworkModule` 默认服务装配与 Addressables 引用。
- README / 开发手册补充"Runtime 服务归业务所有""修改或替换内置服务""定制存档"说明。

## 0.6.0

面向"通用框架"的补强：去掉写死在 Core 里的品类假设，补齐局级作用域、槽位存档、逻辑时间控制。

### 资源

- 新增 `IInstantiateService`（`AddressableAssetService` 实现）：`InstantiateAsync(key, parent, ...)` 按 Addressables key
  实例化预制体，返回 `InstantiatedAsset`，`Dispose` 即回收（销毁对象并释放实例句柄）；`Release(GameObject)` 为等价的显式回收。
- 服务销毁时统一回收所有存活实例，避免切场景后残留。

### 场景

- `ISceneService` 新增 `LoadSceneAdditiveAsync(sceneName, progress, setActive)` 与 `UnloadSceneAsync(sceneName)`：
  支持"常驻主场景 + 关卡/战斗/UI 场景"的叠加模式。
- 每个叠加场景拥有独立的资源作用域（`Additive_{sceneName}`），卸载场景自动回收其资源。

### 输入

- 新增 `IInputService<TFrame>` / `IInputContext<out TFrame>` / `IInputSource<out TFrame>`：
  输入帧类型由业务定义，框架不再假定 `MoveX / MoveY / AttackPressed`。
- 新增 `IInputGate` / `InputGate`（默认服务）：与输入帧无关的模态门闸，可嵌套 `Block(owner)`，
  `IsBlocked` 供任何输入实现查询。UI/对话/过场不再需要伪造"空输入帧"。
- `IInputService`（固定 `InputFrame`）保留为兼容层，`InputService` 现在是 `InputService<InputFrame>` 的子类。
- ⚠ 行为变化：`InputService` / `UIService` 构造函数新增 `IInputGate` 重载；
  使用 `IInputService` 的旧构造方式仍可编译，但推荐注册时注入门闸。

### UI

- `IUIService` 新增 `OpenPanelAsync(string panelKey, object args)`、`ClosePanelAsync(string panelKey)`、`IsOpen(string panelKey)`。
- 新增 `IPanelArguments`：带参数打开时，`SetArguments(args)` 在 `OnShowAsync()` 之前调用。
- UI 输入屏蔽改走 `IInputGate`；`UIService(ILogService, IInputService)` 保留旧行为。

### 容器

- 新增 `ServiceContainer.CreateScope()` → `ServiceScope`：局级作用域，解析顺序"作用域 → 根容器"，
  `Dispose` 只释放作用域内创建的服务。作用域允许在初始化后追加注册（章节/关卡服务）。
- ⚠ `ServiceScope` 内重复注册抛 `Service already registered in scope: X`；环检测消息前缀为 `[Scope]`。

### 存档

- `FileSaveService` 实现新增的 `ISaveSlotService`：槽位路径、`ListSlots`、`SaveToSlotAsync`、`LoadFromSlotAsync`、
  `DeleteSlot`、`ReadThumbnail`。
- 新增 `SaveSlotMetadata` / `SaveSlotInfo`：标题、摘要、游玩时长、保存时间、缩略图字节。
- 元数据为明文 `.meta`（值做 URL 转义），列槽位无需解密存档；缩略图写 `.thumb`。
- 槽位目录默认 `persistentDataPath/Saves`，构造函数可覆盖（便于测试）。
- `SaveToFileAsync` 现在会自动创建目标文件的父目录。

### 时间

- `ITickService` 新增 `IsPaused` / `TimeScale` / `Pause()` / `Resume()`：只缩放逻辑 Tick，不改 `Time.timeScale`。
- `TickService` 的 Tick 回调改为**正序**（注册顺序）执行；`MaxTicksPerFrame` 改为可配置属性。
- `Resume()` 会丢弃暂停期间累加的零头。

### 事件

- `EventBus` 改为 `ConcurrentDictionary<Type, Delegate[]>`：订阅/退订只重建受影响类型的数组，
  不再每次复制整张类型表；`Publish` 无锁遍历快照。
- 新增 `HasSubscribers<T>()`。
- `GetSubscriptionCounts()` 返回 `IReadOnlyList<KeyValuePair<Type, int>>`（此前为字典，遍历方式兼容）。

### 平台（编辑器）

- `ErameSettings` 新增"Steam 语言同步"开关（`steamSyncLanguage`，默认开启）。
- 新增菜单 `Erame/平台/检查 Steam 环境`：逐项检查平台包、Steamworks.NET、`USE_STEAM` 宏、`steam_appid.txt`、
  AppID 是否仍是演示值 480、`steam_api64.dll` 是否就位。
- 新增菜单 `Erame/平台/生成 steam_appid.txt`：按 `ErameSettings.SteamAppId` 写入工程根目录（仅编辑期调试用）。

### 测试与文档

- 新增 `ServiceScopeTests`、`InputGateTests`、`TickServiceTests`、`UIServiceTests`，并补充
  `EventBusTests`（并发订阅退订、`HasSubscribers`）与 `FileSaveServiceTests`（槽位读写/元数据/删除）。
- `开发手册.md` 增补槽位存档、带参数面板、暂停/变速、泛型输入帧与门闸；README 服务表同步。
