# Erame 游戏开发手册

面向已经会 C# 和 Unity 基础操作的开发者，从零创建第一个项目开始，由浅入深覆盖模块、服务、事件、状态机、UI、存档、配置表、平台能力与发布。配套文档：`README.md`（快速上手与菜单速查）、`API.md`（接口速查）。

**阅读约定**

- 所有示例都可以直接放进 `Assets/Game/Scripts/` 下使用（该目录属于 `Game` 程序集，已引用 `Erame.Core` / `Erame.Runtime` / `Game.Runtime`）。
- 底座协议（`IModule` / `IService` / `IServiceRegistrar` / `IFrameUpdate`）在 `Erame.Core`（纯 C#，不依赖 Unity）；业务接口在 `Game.Runtime`，实现在 `Game.Runtime.Services`，都位于生成的 `Assets/Game/Scripts/Runtime`，可自由修改或替换。
- 标注 ⚠ 的是新手最常踩的坑。

## 第 1 章 创建第一个项目

1. 确认 `Packages/manifest.json` 中装有 `com.erame.framework`（嵌入式包或 Git URL 均可），**改包后必须重启 Unity**，否则全项目报 `CS0246: The type or namespace name 'Erame' could not be found`。
2. 菜单 **`Erame/示例/生成项目（按需）`**，勾选这个项目真正需要的能力后生成（想一次要全套就用 `Erame/示例/生成项目（全部能力）`）：
   - 基础能力（日志 / 事件 / 时间 / Tick / 输入门闸）必选；其余按需勾选，缺依赖时窗口会提示"需要一并生成"。
   - 只生成选中能力对应的契约、实现与模块注册；没勾选的服务从一开始就不存在，不用事后删。
   - 随时可以再打开窗口**补生成**：已存在的文件不会被覆盖，只补缺失的。
   生成结构：

```
Assets/Game/
├── Art/            贴图 / 材质 / 模型
├── Audio/
├── Prefabs/
├── Scenes/Game.unity        ← 已挂好 GameEntry 组件
├── Scripts/Game.asmdef      ← 引用 Erame.Core / Erame.Runtime / Game.Runtime
│   ├── GameEntry.cs         ← 你的唯一入口
│   ├── Modules/
│   │   ├── LogModule.cs          一个能力域一个模块，只含勾选的注册行
│   │   ├── EventsModule.cs
│   │   └── …（按本次勾选的能力出现）
│   └── Runtime/
│       ├── Game.Runtime.asmdef
│       ├── Contracts/           接口、DTO、事件（可直接修改或删除）
│       └── Services/            运行时实现（可直接修改或删除）
└── Settings/ErameSettings.asset  ← 框架设置（含 32 字节存档密钥）
```

3. 打开 `Game.unity`，点 Play。Console 出现日志即成功。
4. 菜单 **`Erame/测试/容器快照`**（Play 模式下）可以看到所有已注册服务与初始化顺序——这是排查"某个服务没注册"的第一工具。

## 第 2 章 理解入口 GameEntry

`GameEntry : ErameMonoEntry` 是整个项目唯一的生命周期入口，挂在场景对象上即可：

```csharp
public sealed class GameEntry : ErameMonoEntry{
    public override void Configure(ErameBuilder builder){ /* 注册服务/模块 */ }
    public override void OnStart(){ }            // 启动完成后执行一次
    public override void OnUpdate(float dt){ }   // 每帧执行
    public override void OnQuit(){ }             // 退出前执行一次
}
```

- 入口自动 `DontDestroyOnLoad`；场景里出现第二个入口时只销毁重复实例自身（不会误关容器）。
- `Configure` 抛异常 → 启动失败自动回滚容器，Console 报错后保持未启动状态。

**服务从哪来？两条通道：**

| 通道 | 内容 | 是否需要你写 |
|---|---|---|
| 自动生成的模块（`LogModule` / `EventsModule` / …） | 日志 / 事件 / 时间 / 资源 / 输入 / UI / 池 / 音频 / 本地化 / 存档 / 数据 / 流程 / 命令 / 会话 | 已生成；可删改或替换 |
| 你自己的模块 | 业务服务 | 是，本手册的主体 |

## 第 3 章 创建第一个模块

模块（`IModule`）就是"一组服务的注册清单"。`Configure` 只会被框架统一调用一次，模块之间不依赖注册顺序。

**第 1 步：定义接口**（`Game/Scripts/Services/IGoldService.cs`，业务接口放业务程序集即可）：

```csharp
using Erame.Core;

namespace Game.Scripts.Services{
    public interface IGoldService{
        int Gold { get; }
        void Add(int amount);
        bool TrySpend(int amount);
    }
}
```

**第 2 步：实现**：

```csharp
namespace Game.Scripts.Services{
    public sealed class GoldService : IGoldService{
        private readonly ILogService _log;   // 依赖日志，由容器注入

        public GoldService(ILogService log){ _log = log; }

        public int Gold { get; private set; }

        public void Add(int amount){
            Gold += amount;
            _log.Info($"[Gold] +{amount}，当前 {Gold}");
        }

        public bool TrySpend(int amount){
            if (Gold < amount) return false;
            Gold -= amount;
            return true;
        }
    }
}
```

**第 3 步：建模块**（`Game/Scripts/Modules/EconomyModule.cs`）：

```csharp
using Erame.Core;
using Game.Scripts.Services;

namespace Game.Scripts.Modules{
    public sealed class EconomyModule : IModule{
        public void Configure(IServiceRegistrar registrar){
            // 工厂注册：依赖通过 IServiceProvider.Get 解析，容器负责拓扑排序
            registrar.RegisterSingleton<IGoldService>(p => new GoldService(p.Get<ILogService>()));
        }
    }
}
```

**第 4 步：挂到入口**：

```csharp
public override void Configure(ErameBuilder builder){
    builder
        .AddModule<LogModule>()        // 自动生成的模块按能力域拆分，一行一个
        .AddModule<EventsModule>()
        .AddModule<EconomyModule>();   // 你自己的模块
}
```

之后任何服务都能拿到它：

```csharp
var gold = services.Get<IGoldService>();      // services = ErameRuntime.Services
gold.Add(100);
```

注册方式只有两种（框架刻意不提供 `RegisterService<TI,TImpl>()`——那需要反射）：

| 方式 | 用法 | 场景 |
|---|---|---|
| 实例 | `RegisterSingleton(new GoldService(log))` | 对象已创建好 |
| 工厂 | `RegisterSingleton(p => new GoldService(p.Get<ILogService>()))` | 需要注入依赖（默认选择） |

### 3.x 注册与使用的规范（模块多了怎么找注册点）

**先分清两个时机：**

| 阶段 | 能做什么 | 说明 |
|---|---|---|
| `Configure` 阶段（Build 前） | **只能注册** | `Configure` 只拿到 `IServiceRegistrar`，没有 Get；工厂 lambda 只是被存起来，不执行 |
| Build / InitializeAll 阶段 | 工厂执行、依赖 Get 发生 | 容器按依赖拓扑序构造，所以"E 模块工厂里 Get G"不要求 G 先注册，只要求 Build 前注册齐 |
| 启动完成后（`OnStart` 之后） | 任何地方 `ErameRuntime.Services.Get<T>()` | 运行时使用 |

**三条规范：**

1. **一服务一注册点**：`GoldService` 全项目只在一个模块里 `RegisterSingleton`，重复注册会直接报错 `Service already registered`，不存在静默覆盖。
2. **注册点可预测**：接口 ↔ 实现 ↔ 注册模块**同领域对位**——`IGoldService`/`GoldService` 注册在 `EconomyModule`；框架服务的注册点就是同名的 `*Module`（`IUIService` → `UIModule`）。写定之后不要搬家，目录约定就是索引。
3. **使用方不需要模块身份**：其他模块在自己服务的工厂里 `p.Get<G>()`（构建期注入），或运行时 `Services.Get<G>()`，都与"谁注册的"无关——容器没有模块概念，注册顺序无关。

**不确定在哪注册的，直接查：** Play 模式下菜单 **`Erame/测试/容器快照`**，每个服务显示注册来源：

```
注册服务 (26)：
  ILogService ← LogModule
  IGoldService ← EconomyModule
  IUIService ← UIModule
  IMyPlatformService ← MyPlatformModule
  ...
```

（来源由框架在逐模块 Configure 时自动打标签：`入口 GameEntry` / 模块类名 / 平台模块类名。）

## 第 4 章 服务生命周期

让服务实现 `IService` 可以获得初始化/清理时机：

```csharp
public sealed class GoldService : IGoldService, IService{
    public void Initialize(){ /* 容器 Build 后统一调用 */ }
    public void Dispose(){ /* 逆序清理 */ }
}
```

规则（由 `ServiceContainer` 保证）：

- **初始化按依赖拓扑序**：`GoldService` 依赖 `ILogService`，日志一定先 `Initialize`。
- **失败自动回滚**：任一服务 `Initialize` 抛异常，已初始化的服务按逆序 `Dispose`，启动中止。
- **清理逆序**：`Quit` 时后初始化的先 Dispose。
- **重复注册直接抛错** `Service already registered: IGoldService`——同一接口注册两次是 bug，不是"后者覆盖前者"。
- **循环依赖直接抛错**，错误信息带完整链路 `[Container] 检测到循环依赖: A -> B -> A`。
- `Build()` 之后不允许再注册。

## 第 5 章 第一个事件

事件必须是 `struct`（值类型，零 GC），订阅/发布都走 `IEventBus`：

```csharp
// 1. 定义事件
public readonly struct GoldChangedEvent{
    public readonly int NewGold;
    public GoldChangedEvent(int newGold){ NewGold = newGold; }
}
```

```csharp
// 2. 订阅（返回 IDisposable 凭证，Dispose 即退订）
IDisposable sub = eventBus.Subscribe<GoldChangedEvent>(e => {
    log.Info($"金币变化: {e.NewGold}");
});

// 3. 发布（in 参数，不拷贝）
eventBus.Publish(new GoldChangedEvent(100));

// 4. 退订：调用 Unsubscribe，或直接 sub.Dispose()
sub.Dispose();
```

要点：

- ⚠ **订阅要持有凭证**。在入口里订阅是安全的（入口生命周期 = 游戏生命周期）；在面板/临时对象里订阅，必须在销毁时 `Dispose` 凭证，否则回调打到已销毁对象。
- 某个订阅者抛异常**不影响其他订阅者**，异常会经 `ILogService.Error` 上报。
- 调试：菜单 **`Erame/测试/事件统计`** 可列出每个事件类型的订阅者数量（Play 模式）。

## 第 6 章 第一个固定逻辑 Tick

`ITickService` 提供固定步长逻辑帧（默认间隔 0.1 秒），由 `ErameRuntime.Update` **自动驱动**，你只管挂监听：

```csharp
var tick = services.Get<ITickService>();
tick.TickInterval = 0.1f;                      // 一秒 10 Tick
tick.AddTickListener(OnLogicTick);             // 每 Tick 调用，按注册顺序执行
// tick.RemoveTickListener(OnLogicTick);       // 移除
// tick.CurrentTick                            // 当前 Tick 序号（游戏内时间）

tick.Pause();                                  // 暂停逻辑时间（不影响渲染、动画、UI）
tick.Resume();                                 // 恢复；暂停期间的零头会被丢弃
tick.TimeScale = 2f;                           // 2 倍速推进（0 = 冻结，负值按 0 处理）
```

`Pause` / `TimeScale` 只缩放**逻辑 Tick**，不会修改 `Time.timeScale`，因此 UI 动画、粒子、音频不受影响。
需要"整局慢放/暂停画面"时再自行改 `Time.timeScale`，两者互不干扰。

适合：回合计时、AI 决策、 buff 结算——所有不该跟随帧率的逻辑。

## 第 7 章 第一个游戏状态机

框架提供纯 C# 状态机（`IGameState` / `IGameStateMachine`），典型切法：`BootState → MainMenuState → GameplayState`。

**第 1 步：写状态**：

```csharp
using Game.Runtime;

namespace Game.Scripts.States{
    public sealed class BootState : IGameState{
        public void OnEnter(){ /* 加载存档、进主菜单 */ }
        public void OnUpdate(){ }
        public void OnExit(){ }
    }

    public sealed class MainMenuState : IGameState{
        public void OnEnter(){ /* 打开主菜单面板 */ }
        public void OnUpdate(){ }
        public void OnExit(){ }
    }
}
```

**第 2 步：注册并切换**。⚠ 两点注意：

1. `RegisterState` 定义在具体类 `GameStateMachine` 上（接口只有 `ChangeState<T>` / `Update`），需要转换一下：

```csharp
if (services.Get<IGameStateMachine>() is GameStateMachine machine){
    machine.RegisterState(new BootState());
    machine.RegisterState(new MainMenuState());
}
```

2. ⚠ **状态机的 `Update()` 不会自动调用**，框架只自动驱动实现了 `IFrameUpdate` 的服务（Tick、平台回调等）。状态机需要在入口里手动驱动：

```csharp
public override void OnUpdate(float deltaTime){
    services.Get<IGameStateMachine>().Update();
}
```

**第 3 步：切换状态**（任何地方）：

```csharp
services.Get<IGameStateMachine>().ChangeState<MainMenuState>();
```

未注册就切换会得到 `[StateMachine] 未注册状态: MainMenuState` 的错误日志（不会抛异常打断游戏）。

## 第 8 章 第一个 UI 面板

UI 是"面板栈"模型：`Open` 压栈并自动隐藏下层面板，`CloseTop` 出栈并重新显示下层；第一个面板打开时自动压入 **UI 输入上下文**（游戏操作被屏蔽），栈清空时自动恢复。

**第 1 步：实现 `IUIPanel`**（建议做成预制体上的 MonoBehaviour 组件）：

```csharp
using System.Threading.Tasks;
using Game.Runtime;
using UnityEngine;

namespace Game.Scripts.UI{
    public sealed class MainMenuPanel : MonoBehaviour, IUIPanel{
        private ILogService _log;
        private IEventBus _events;
        private IDisposable _goldSub;

        public string PanelKey => "MainMenu";

        // 由业务在注册前调用一次（框架不负责创建面板对象）
        public void OnCreate(ILogService log, IEventBus eventBus){
            _log = log;
            _events = eventBus;
        }

        public Task OnShowAsync(){
            _goldSub = _events.Subscribe<GoldChangedEvent>(e => Refresh(e.NewGold));
            _log.Info("[UI] 主菜单显示");
            return Task.CompletedTask;
        }

        public Task OnHideAsync(){
            _goldSub?.Dispose();   // 面板隐藏即退订事件
            _goldSub = null;
            return Task.CompletedTask;
        }

        public void OnDestroy(){ }

        private void Refresh(int gold){ /* 更新金币文本 */ }
    }
}
```

**第 2 步：注册**（在模块或入口里，对象的创建方式由你决定——Addressables 加载、场景常驻等）：

```csharp
var panel = prefab.GetComponent<MainMenuPanel>();
panel.OnCreate(services.Get<ILogService>(), services.Get<IEventBus>());
ui.RegisterPanel(panel);
```

**第 3 步：开合**：

```csharp
await ui.OpenPanelAsync("MainMenu");                 // 压栈
await ui.OpenPanelAsync("Shop", new ShopArgs{ ... }); // 带参数：面板实现 IPanelArguments 即可收到
await ui.CloseTopPanelAsync();                        // 出栈
await ui.ClosePanelAsync("Shop");                     // 关闭指定面板（不必是栈顶）
bool open = ui.IsOpen("Shop");
await ui.CloseAllAsync();
```

带参数时，`SetArguments(args)` 在 `OnShowAsync()` **之前**调用，面板可以在这里绑数据、刷新列表，`OnShow` 只负责呈现。

```csharp
public sealed class ShopPanel : IUIPanel, IPanelArguments{
    private ShopArgs _args;
    public string PanelKey => "Shop";

    public void SetArguments(object args) => _args = args as ShopArgs;

    public Task OnShowAsync(){
        OpenWith(_args?.NpcId);   // 参数已经准备好了
        return Task.CompletedTask;
    }
}
```

面板操作全部串行化（内部有信号量），快速连点不会打乱栈与输入状态。
输入屏蔽走 `IInputGate`（`InputModule` 注册）：第一个面板打开时 `Block()`，栈空时归还，因此任何输入方案（新旧 Input System、事件驱动）都能用同一个门闸判断"现在是否该吃游戏输入"。

## 第 9 章 资源与场景

资源走 Addressables（`AssetsModule` 已注册 `IAssetService`，前提是工程装了 `com.unity.addressables`），前置依赖可用菜单 `Erame/诊断/框架自检` 检查。

```csharp
// 加载：key 是 Addressables 的地址；句柄必须释放（引用计数）
AssetHandle<GameObject> handle = await assets.LoadAsync<GameObject>("prefab/player");
Instantiate(handle.Asset);
handle.Dispose();          // 引用计数 -1，允许卸载；重复 Dispose 安全

// 进度与取消
var handle2 = await assets.LoadAsync<Texture2D>("tex/sky", progress, cancellationToken);

// 作用域：同一作用域内的资源可被统一释放
IAssetScope scope = assets.CreateScope("Chapter01");
```

场景切换：

```csharp
await scenes.LoadSceneAsync("Level01", progress);   // 单场景：卸载当前场景后加载
var scope = scenes.CurrentScope;                    // 当前场景的资源作用域

// 叠加加载：常驻主场景 + 关卡/战斗场景
await scenes.LoadSceneAdditiveAsync("Battle01", progress, setActive: false);
await scenes.UnloadSceneAsync("Battle01");          // 同时回收它的资源作用域
```

⚠ `AssetHandle<T>` 用完必须 `Dispose`，否则资源引用计数永远不归零、内存不回收。

### 9.x 直接实例化预制体

列表项、单位、建筑、掉落物这类"加载完马上就要一个场景对象"的东西，用 `IInstantiateService`
（`AddressableAssetService` 同时实现；`AssetsModule` 已注册）比"加载 + Instantiate + 自己管句柄"更省事：

```csharp
// 短生命周期：块结束时自动回收（一次性特效、临时提示）
using (var fx = await spawner.InstantiateAsync("fx/explosion", parent)){
    fx.GameObject.transform.position = pos;
}

// 长生命周期：由业务持有引用，对象销毁时手动回收
InstantiatedAsset unit = await spawner.InstantiateAsync("unit/soldier", parent);
if (unit != null){
    var view = unit.GetComponent<UnitView>();
    // ……
    unit.Dispose();                 // 或 spawner.Release(unit.GameObject)
}
```

- `InstantiateAsync(key, parent, worldPositionStays, progress, cancellationToken)`：取消不会泄漏句柄，失败返回 `null`。
- `InstantiatedAsset.Dispose()` / `_spawner.Release(go)`：销毁对象并释放实例句柄，重复调用安全。
- 高频对象建议 `InstantiateAsync` 拿到后交给 `IPoolService`，`Despawn` 时再 `Dispose` 或复用，避免频繁 Instantiate/Destroy。
- 服务销毁（退出游戏/切工程）时会统一回收所有仍存活的实例。

## 第 10 章 第一个存档

存档 = 若干 `ISaveable` 对象把自己的数据写进同一份文件（AES-GCM 加密、原子写入、保留 `.bak`）。

**第 1 步：让数据类实现 `ISaveable`**：

```csharp
using Game.Runtime;

namespace Game.Scripts.Save{
    public sealed class PlayerData : ISaveable{
        public string SaveKey => "PlayerData";     // 文件内唯一标识
        public int Level;
        public int Exp;

        public void Save(SaveWriter writer){
            writer.Write(Level);
            writer.Write(Exp);
        }

        public void Load(SaveReader reader){
            Level = reader.ReadInt();
            Exp = reader.ReadInt();
        }
    }
}
```

⚠ `Save` / `Load` 的字段顺序必须完全一致，否则整份存档错位。

**第 2 步：注册并读写**：

```csharp
var player = new PlayerData();
save.Register(player);                                       // 进入存档集合
await save.SaveToFileAsync(Path.Combine(Application.persistentDataPath, "save.dat"));
await save.LoadFromFileAsync(Path.Combine(Application.persistentDataPath, "save.dat"));
save.Unregister(player);                                     // 不再参与存档时移除
```

`SaveWriter` / `SaveReader` 支持：`int` / `float` / `bool` / `string` / 原始字节。

**存档槽位（读档界面用）**。`FileSaveService` 同时实现 `ISaveSlotService`，槽位文件落在 `persistentDataPath/Saves/slot_{n}.sav`，
旁边有明文 `.meta`（标题/摘要/游玩时长/保存时间）与可选 `.thumb`（截图字节）。列槽位**不解密存档**，读档界面的打开速度与存档大小无关：

```csharp
var slots = saves.ListSlots(8);                 // 扫描 0..7，不存在的槽位 Exists = false
foreach (var slot in slots){
    if (slot.Exists) Draw(slot.Title, slot.Summary, slot.PlayTimeSeconds, slot.SavedAtUtc);
}

await saves.SaveToSlotAsync(3, new SaveSlotMetadata{
    Title = "第三章 · 雨夜",
    Summary = "资源 120 / 人口 34",
    PlayTimeSeconds = 3600 * 5.5,
    Thumbnail = screenshotPngBytes,              // 可为 null
});

await saves.LoadFromSlotAsync(3);
byte[] thumb = saves.ReadThumbnail(3);           // 没有则返回 null
saves.DeleteSlot(3);                             // 存档/备份/元数据/缩略图一起删
```

⚠ 缩略图字节原样写盘，请自行压缩（建议 ≤ 256×144 的 JPG/PNG）；元数据只是展示信息，写失败不会影响存档本身。

**想定制存档**：`FileSaveService` 就在 `Runtime/Services/Save/FileSaveService.cs`，可以直接改（加密、分块、异步策略都在实现里）；也可以删掉 `SaveModule` 里的注册，换成自己的 `ISaveService` 实现。需要全新契约时，在业务程序集新增接口即可，`Erame.Core` 不需要改。

**密钥**：来自 `Settings/ErameSettings.asset` 的 `saveKey`（32 字节）。⚠ 发布前必须填固定值——未配置时使用 PlayerPrefs 开发期密钥，换机器后旧存档无法解密。菜单 `Erame/配置/校验框架设置` 可体检。

## 第 11 章 配置表（CSV）

配置表是纯 C#：行类实现 `IData`，解析**不使用反射**（列映射由你显式写）。

**第 1 步：行类**：

```csharp
using Game.Runtime;

public sealed class ItemConfig : IData{
    public int Id { get; set; }          // 必须：主键，表内不允许重复
    public string Name { get; set; }
    public int Price { get; set; }
}
```

**第 2 步：解析 CSV**（首行为表头）：

```csharp
using Game.Runtime;
using Game.Runtime.Services;

DataTable<ItemConfig> table = CsvParser.Parse(
    csvText,
    logger,
    rowFactory: () => new ItemConfig(),
    applyColumn: (row, column, raw) => {
        switch (column){
            case "Id":    row.Id = int.Parse(raw);    break;
            case "Name":  row.Name = raw;             break;
            case "Price": row.Price = int.Parse(raw); break;
        }
    });
```

**第 3 步：注册进数据表仓库并查询**：

```csharp
dataRegistry.Register("ItemConfig", table);

var itemTable = dataRegistry.Get<ItemConfig>("ItemConfig");
ItemConfig sword = itemTable.Get(1001);        // 按 Id 查找
bool ok = itemTable.TryGet(1002, out var item);
```

- 重复 `Id` 会抛 `数据表中存在重复的 ID: xxx`。
- 单元格解析失败只记警告日志，不中断整表加载。

## 第 15 章 平台能力（由开发者自行实现）

框架不再提供 Steam / Epic / Wegame 平台包，也不内置任何平台 SDK 封装。需要平台能力时，直接在业务工程里实现：

1. 定义自己的平台接口（例如 `IMyPlatformService`）。
2. 实现接口（Steam SDK 初始化、回调泵、成就、云存档等都由你决定）。
3. 写一个 `IModule` 注册服务；入口 `builder.AddModule<MyPlatformModule>()`。
4. 服务需要每帧更新时实现 `IFrameUpdate`，`ErameRuntime` 会自动驱动，不需要在入口手动调用。

```csharp
public sealed class MyPlatformModule : IModule{
    public void Configure(IServiceRegistrar registrar){
        registrar.RegisterSingleton<IMyPlatformService>(p => new MyPlatformService(p.Get<ILogService>()));
    }
}
```

`Erame.Core` 只提供 `IModule` / `IServiceRegistrar` / `IFrameUpdate` 这些底座协议，不限制你使用哪个 SDK、如何组织接口。包内 `Samples~/Platform` 是历史实现归档，不参与编译，可作参考。

## 附录：输入帧与门闸

框架不再假定输入帧长什么样：`InputFrame`（`MoveX/MoveY/AttackPressed`）只是**默认示例**，任何品类都可以定义自己的帧类型：

```csharp
public readonly struct BuildFrame{
    public readonly float PanX, PanY, Zoom;
    public readonly bool Confirm;
    public BuildFrame(float x, float y, float z, bool confirm){ PanX = x; PanY = y; Zoom = z; Confirm = confirm; }
}

// 模块里注册自己的帧类型（UIService 用 IInputGate 屏蔽输入，与帧类型无关）
registrar.RegisterSingleton<IInputService<BuildFrame>>(p =>
    new InputService<BuildFrame>(p.Get<ILogService>(), p.Get<IInputGate>()));
```

- `IInputService<TFrame>`：`SetSource` / `GetCurrentFrame` / `PushContext` / `PopContext`，上下文按 `Priority` 稳定排序。
- `IInputGate`（`InputModule` 注册）：`gate.IsBlocked` 查询是否该吃游戏输入；`gate.Block(owner)` 返回凭证，`Dispose` 归还，可嵌套。UI/对话/过场共享同一个门闸，任何输入实现都能接入。

旧的 `IInputService`（固定 `InputFrame`）保留为兼容层，新项目建议直接用泛型版本。

## 附录：常见问题

| 症状 | 原因与解法 |
|---|---|
| 全项目 `CS0246: 'Erame' could not be found` | 嵌入式包改了但 Unity 没重启——重启编辑器 |
| `Service already registered: Xxx` | 同一接口注册了两次，检查各模块是否重复注册 |
| `Service already registered in scope: Xxx` | 同一局作用域里重复注册，改用 `CreateScope()` 新建一层 |
| 不知道某服务在哪个模块注册的 | Play 下 `Erame/测试/容器快照`，看每个服务的 `← 来源` 标签 |
| 平台服务拿不到 | 平台能力由业务自行实现：确认自己的 `IModule` 已在入口 `AddModule` 并注册了对应服务 |
| 状态机切换无反应 / 不更新 | `RegisterState` 未调用（看日志"未注册状态"）；`Update()` 需在入口 `OnUpdate` 手动驱动 |
| 面板打开无反应 | `OpenPanelAsync` 的 key 与 `PanelKey` 不一致（面板没注册时静默返回） |
| 面板收不到参数 | 面板没实现 `IPanelArguments`（不实现时参数被忽略，保持旧行为） |
| 打开 UI 后角色还能动 | 注册 `IUIService` 时传了 `IInputService` 而不是 `IInputGate`，或自定义输入实现没查 `gate.IsBlocked` |
| 事件没人响应 | 订阅对象已销毁？`Erame/测试/事件统计` 看订阅数；订阅凭证是否 Dispose 过早 |
| 资源内存不回收 | `AssetHandle<T>.Dispose()` 没调用 |
| 旧存档打不开 | `ErameSettings` 换过密钥；发布前务必固定密钥 |
| 场景里入口没启动 | 对象没激活、`m_Script` 引用丢失（重新挂 `GameEntry` 组件） |
